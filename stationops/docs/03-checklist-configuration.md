# 3. Checklist configuration

The demo's 8 tasks are **samples only**. Real tasks must be written with, and approved by, the restaurant manager before go-live.

## Writing good tasks

- **One action per task, starting with a verb:** "Check walk-in cooler is 41°F or below", not "Fridge".
- **Put limits in the task** (temperatures, counts, dates) so "done" means the same thing to everyone.
- **Mark a task Required** if the station must not open without it. Mark it optional only if skipping it is acceptable.
- **Keep it short:** 6–12 tasks. A list that takes longer than the opening allows will be skipped.
- **Order tasks the way people walk the station.**

## Entering it

1. Sign in as a manager and open **Checklists**.
2. If the station has no checklist yet, use **New opening checklist**. Otherwise click **Edit tasks**.
3. Type each task. Use **↑ Up / ↓ Down** to order them, **Remove** to drop one, and the **Required** box to set required/optional.
4. In **What changed?**, write something like "Approved by [manager], [date]".
5. Click **Save new version**.
6. Check the **Version history** panel shows the new version.

## How changes behave

- Saving creates a **new version**. Checklists started from then on use it.
- Checklists already started today, and all past checklists, keep the wording they were given. History is never rewritten.
- To roll back, re-enter the earlier wording (shown by clicking an older version) and save. That becomes the newest version.
